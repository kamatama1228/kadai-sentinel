# 自分用のコードで拡張する(custom/)

設定([CUSTOMIZE.md](CUSTOMIZE.md))ではできないことを、本体のファイルを変えずに足すための仕組みです。
自分用のコードは `custom/` フォルダに置きます。`custom/` は Git に入らないので、本体を更新(`git pull`)してもぶつかりません。

> このツールは、これからも本体を直しながら育てていくものです。本体のファイルを直接書き換えると、更新のたびにぶつかります。自分用の変更は `config/`(設定)と `custom/`(コード)だけに置いてください。

## できること(拡張口 1 版)

今ある拡張口は「送る直前の通知を書き換える」1つです。

| ファイル | 関数 |
| --- | --- |
| `custom/hooks.ts` | `beforeSend(notices, ctx)` |

- 通知の配列を受け取り、**送りたい通知の配列を返します**。文面を書き換える・消す・足す、のどれもできます
- `ctx.channel` は送り先(`"shared"` 共有 / `"personal"` 個人)、`ctx.now` は今の時刻(UNIX 秒)、`ctx.local` は今の日時(`h` 時、`mi` 分、`dow` 曜日。月曜=0)
- 共有チャンネルと個人チャンネルで、別々に呼ばれます
- `mute`(設定で消す通知)が効いたあとの通知が渡されます
- **エラーになったり、形のおかしいものを返したりしたら、その回はなかったことにして元の通知を送ります。** 自分用のコードが壊れても、通知が届かなくなることはありません

通知(`Notice`)の主な中身:

| 項目 | 意味 |
| --- | --- |
| `heading` | 見出し(「🚨 小テストが公開されました」など) |
| `course` / `courseId` | 授業名 / 授業ID |
| `title` | 課題・小テストの名前 |
| `url` | Moodle のリンク |
| `fields` | 「締切」「受付」などの欄。`[名前, 値]` の配列 |
| `urgent` | 急ぎ(公開中の小テストなど)。まとめずに単独で送る |

## はじめ方

1. 例をコピーする
   ```powershell
   mkdir custom
   Copy-Item examples\custom\hooks.ts custom\hooks.ts
   ```
2. 書き換える(例では「個人チャンネルの見出しに 📌 をつける」「夜中のお知らせは送らない」をしています)
3. 確かめる:`uv run moodle config check`(`custom/hooks.ts` が読み込めるかも調べます)
4. 反映する:`cd worker` → `npm run deploy`
5. Cloudflare 版は `npx wrangler tail` を開いて、`custom/hooks.ts の beforeSend が失敗` と出ていないか、1〜2 回の確認を見届けます

## 約束

- 本体のファイル(`worker/` `core/` `cli/` `schema/`)は書き換えず、型や部品を読むだけにする
- 通知を増やしすぎない。特に共有チャンネル(友達全員)に足すときは、共有チャンネルを動かしている人と相談する
- `.env` の中身(トークン・Webhook)をコードに書かない
- ネットワークに出ていくコード(よそのサービスに送るなど)を書かない

## 本体を直す人へ(拡張口を変えるとき)

- 拡張口の形は `worker/src/hooks.ts` の `HOOKS_API` が表します(今は 1)。変えたら CHANGELOG.md の「更新したらやること」に、`custom/` の直し方を書く
- 引数の形を変える・関数名を変えるなど、今ある `custom/` が動かなくなる変更をするときは、数字を上げてこのページに書く。できるだけ、古い形も受け付けるようにする
- 新しい拡張口(たとえば「通知を足す」「授業の判定を変える」)を増やすときも、同じファイルに足し、失敗したら元の動きに戻るようにする
- 設定の項目を増やすときは、`schema/` の JSON Schema、`worker/src/rules.ts`、CUSTOMIZE.md、`worker/test/` のテストをそろえて直す
- どの変更でも、前と後に `cd worker` → `npm test` を実行する。新しい動きにはテストを足す
