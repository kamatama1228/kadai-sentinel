# 自分用にカスタマイズする

通知の内容やタイミングを、自分用に変えるための手順と、安全に変えるための約束です。
**上から順に、まず設定だけで済まないかを考えてください。** AI(Claude・Antigravity など)に「〇〇の通知をやめたい」と頼むと、このページと `AGENTS.md` の決まりに沿って `notify.toml` を書き換えてくれます。 下に行くほど自由ですが、壊したときに直すのが大変になります。

| やりたいこと | 方法 | 更新(`git pull`)とぶつかるか |
| --- | --- | --- |
| どの授業を、いつ知らせるかを変える | 1. `notify.toml` を書き換える | ぶつからない |
| 特定の通知だけ消したい | 2. `notify.toml` の `[[mute]]` | ぶつからない |
| 文面や仕組みそのものを変えたい | 3. 自分用のブランチ・fork でコードを変える | ぶつかることがある |

> `notify.toml` と `.env` は Git に入らないファイルです。いくら変えても、本体の更新とぶつかりません。

---

## 1. notify.toml で変えられること

| 項目 | 場所 | 例 |
| --- | --- | --- |
| 共有チャンネルに流す授業と、流すもの | `[course.授業ID]` の `enabled` `events` `kinds` `match` | 小テストの公開だけ流す |
| 締切の何前に知らせるか | `[course.授業ID]` / `[personal]` / `[personal.course.授業ID]` の `remind` | `["7d", "1d"]`、`["@16:30"]`(締切日の 16:30) |
| 個人通知のいらない授業 | `[personal]` の `exclude` | `[10001, 10002]` |
| 共有チャンネルの通知を個人にも送る | `[personal]` の `mirror_shared` | `true` |
| 共有にない授業の締切変更を知らせる | `[personal]` の `changes` | `true` / `false` |
| 共有にない授業の「お知らせ」 | `[personal]` の `news`・`news_keywords` | `"keywords"`(休講などだけ)/ `"all"` / `"off"` |
| オンライン授業の朝の通知 | `[online]` の `enabled` `shared` `keywords` `exclude` | 録画の視聴は除く |
| 授業の曜日(出欠の予定がない授業用) | `[course.授業ID]` / `[personal.course.授業ID]` の `days` | `["thu"]` |
| 朝の予告の時刻 | `[watch]` の `morning_at` | `"07:30"` |
| ふだん確認する時刻 | `[watch]` の `schedule` | `["10:00", "22:00"]`(1日 12 回まで) |
| 1分おきに確認する時間帯 | `[watch]` の `fast_windows` | 小テストがある授業の時間(1つ 4 時間まで) |

授業 ID は `uv run moodle courses` で分かります。

**変えたあと**:Cloudflare 版を使っている人は `cd worker` → `npx wrangler deploy` で反映します。
書き方を間違えると、通知が止まる代わりに **個人チャンネルに「notify.toml に誤りがあり、通知が止まっています」と届きます**(1日1回)。直して deploy し直してください。

## 2. 特定の通知だけ消す([[mute]])

`notify.toml` に書くだけで、コードを触らずに通知を消せます。条件をすべて満たす通知だけが消えます。

```toml
# 授業ID 10004 の通知は、個人チャンネルには送らない
[[mute]]
channel = "personal"   # shared(共有)/ personal(個人)/ both(両方。既定)
course = 10004

# 「お知らせ」の通知は全部いらない
[[mute]]
heading = "お知らせ"

# 名前に「アンケート」を含むものはいらない
[[mute]]
title = "アンケート"
```

- 条件(`course` `title` `heading`)が 1 つもない `[[mute]]` は、全部消えてしまうのでエラーになります
- `channel = "shared"` や `both` は、共有チャンネル(友達全員)にも効きます。共有チャンネルを動かしている人以外は使わないでください

## 3. コードを変えたいとき

文面を変えたい、新しい通知を足したい、などはコードの変更になります。次の順で進めると安全です。

1. **まず相談する。** みんなに役立つ変更なら、本体に入れたほうが全員が楽です
2. **自分用のブランチを作ってから変える**
   ```powershell
   git switch -c my-custom
   ```
   本体を更新するときは `git switch main` → `git pull` → `git switch my-custom` → `git merge main`。同じ場所を変えているとぶつかるので、そのときは AI に「merge のぶつかりを直して」と頼む
3. **大きく作り変えるなら fork(自分用のコピー)** にする。本体の更新は GitHub の画面の「Sync fork」で取り込める
4. **変えたら必ず試す**
   - `uv run moodle notify --test personal` で、自分のチャンネルに見本の通知が届くか
   - Cloudflare 版は deploy 後に `npx wrangler tail` を開いて、エラーが出ていないか(1〜2 回の確認を見届ける)

### 変えるときの約束(通知が止まる・増えすぎるのを防ぐため)

- **共有チャンネルの Webhook(`DISCORD_WEBHOOK_URL`)は、共有チャンネルを動かしている 1 人だけが持つ。** ほかの人は `.env` で空のままにする(同じ通知が友達全員に何重にも届くのを防ぐ)
- **確認の間隔を短くしない。** `fast` を 1m より短く、`fast_windows` を長くすると大学のサーバーに負担がかかる(書けないように上限がある)
- `worker/src/index.ts` の「送る前に保存する」「送り直し」「確認中の印」の部分は、通知の二重送信・取りこぼしを防ぐ仕組みなので変えない
- `.env`(トークン・Webhook)を AI のチャットや GitHub に貼らない
- 困ったら元に戻す:`git stash`(変更をよける)、`git switch main`(本体に戻る)、`notify.toml` は `state/notify.toml.bak` にコピーを取ってから変える(`state/` は Git に入らない)

## 安全のための仕組み(最初から入っているもの)

| 起きること | どうなるか |
| --- | --- |
| notify.toml の書き間違い | 通知は止まるが、個人チャンネルに 1 日 1 回知らせる |
| Moodle が止まった・トークン切れ | 個人チャンネルに知らせる(24 時間に 1 回) |
| Discord に送れなかった | 送れなかった分だけ、あとで送り直す(締切を過ぎたものは送らない) |
| 一度にたくさん出た | 4 件以上は 1 通にまとめる(急ぎのものも) |
| 確認が重なった | 同じ通知を二重に送らない |
| 1 つの授業だけ情報が取れない | その授業だけ飛ばして、ほかは通知する |

> PC で動かす版(`uv run moodle watch`)は、オンライン授業の朝の通知・お知らせ・締切変更・`[[mute]]` には対応していません(Cloudflare 版のみ)。
